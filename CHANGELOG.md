## v0.20.0 — 2026-07-18

Full Krea 2 model-family support · fp8 base-model training and inference · VRAM policies and orchestration · unified model-source management · autosaving presets

### Added

- **Krea 2 model family: the full pipeline from training to generation (#408–#425)**
  The training config gains a model-family selector: besides Anima you can now train Krea 2 (a 12.9B single-stream MMDiT with Qwen3-VL text encoding) — LoRA training on the Raw base, samples during training, AI-generated regularization sets, post-training evaluation, and test generation (including 8-step distilled Turbo) all work end to end; output LoRAs interoperate directly with ComfyUI (the Euler + Simple sampling combo matches word for word). See the "Krea 2 support is here" announcement for getting started and training tips.

  - The download center is grouped by family: Krea 2 Raw / Turbo each come in bf16 and official fp8, the text encoder toggles bf16 / fp8; the VAE is shared with Anima, no duplicate download
  - Switching families is a confirmed action: a dialog itemizes every weight path and family default about to be recomputed before anything changes; option dropdowns filter per family, and Anima-only features (NaViT, tag shuffle, etc.) hide automatically on Krea 2
  - Training pre-encodes all captions into a text cache and releases the text encoder by default (saving about 9 GB of VRAM); high-VRAM cloud setups can disable it to keep the encoder resident
- **fp8 base models: training and inference across the board (#426, #434, #435, #436, #437, #444)**
  Official fp8 weights now work as both training and inference base models — pick the fp8 file and it just works, no extra switch. For training (fp8_base), weight VRAM drops 25.6 → 13.1 GB, bringing Krea 2 training down to 24 GB-class GPUs; for inference, resident VRAM is roughly halved, with LoRAs applied via merge-writeback that matches ComfyUI output bit for bit.

  - XY grids support the LoRA-strength axis on fp8 bases (re-merged per cell); LoHa and rs-LoRA load on fp8 bases, DoRA is not supported yet
  - The official fp8 text encoder (5.2 GB) works for both training and generation — one download covers everything; switching precision rebuilds the text cache automatically
- **VRAM and RAM orchestration (#427, #437, #438, #439)**
  Test generation gains a three-level VRAM policy (default·release-after-use / save VRAM / performance): each task pre-encodes all prompts into a cache and releases the text encoder, so it occupies zero VRAM during sampling — a 16 GB GPU can generate with Krea 2 fp8 on the "save VRAM" setting; evaluation and regularization generation use the same orchestration. Loading large weights is now guarded by a RAM check that fails with an actionable error instead of freezing the whole machine in page thrash. "Free VRAM" now actually frees everything (clears leftover cuBLAS workspaces).
- **Community LoRAs from civitai load directly (#426, #428)**
  Krea 2 community LoRAs in PEFT / comfy key format (the common civitai shape) now load directly on the Test page, on both bf16 and fp8 bases, no conversion needed.
- **Unified model-source management (#446)**
  Swapping models for WD14 / CLTagger / eval metrics / upscalers / training base models now uses one shared pattern: a candidate list (built-ins + your additions) with "add download" and "add local file" entries at the bottom; local-file candidates are only ever removed from the list — your files are never deleted. Old configs migrate automatically with selections preserved.
- **One editor for LLM tagger presets (#445)**
  LLM tagger preset editing is consolidated into a single global editor (Settings and the Tagging page open the same one), ending field drift between the two; the Settings LLM section becomes a preset management list (default radio + create / edit), the Tagging page keeps just the per-run preset choice; edits made in Settings take effect on the Tagging page immediately.
- **Generate page: persistent base/TE choice + token count (#441)**
  Your base model and text encoder picks on the Test page are now remembered across pages and sessions (unset = follow global Settings); the prompt box shows a token count; online generation no longer silently truncates prompts beyond 512 tokens.
- **Generation task timeout (#443)**
  An optional task timeout (off by default) force-kills the inference process when the machine is wedged, marks the task failed, and reloads on the next task — no more reboots.

### Changed

- **Default LoRA type for new configs: lokr → lora (#442)**
  New projects and presets default `lora_type` to classic LoRA; existing configs with an explicit value are unaffected.
- **Downloaded assets in the download center now offer "delete" (#437, #442)**
  The implicit overwrite of "re-download" is retired: delete first, then download; tagger / eval / upscaler sections get delete too.
- **Config exclusion rules enforced on both ends + linked-change confirmation (#431, #432)**
  Parameter exclusions declared in the UI are now enforced by the backend as well: invalid combinations in hand-written yaml / CLI fail at startup with a reason instead of passing silently; when a UI change triggers linked field rewrites (e.g. NaViT forcing the attention backend), a dialog lists the changes for confirmation first. The YAML preview is now physically the same serialization as what lands on disk.

### Improved

- **Presets page autosaves + unified save indicator (#433)**
  The global presets page now autosaves like the Train and Settings pages (600ms debounce) — no more save button for existing presets; Train / Presets / Settings share the same "✓ saved" indicator; disabled inputs are now visibly grayed out.

### Fixed

- **Training configs didn't follow a global model re-selection (#439)**
  After picking a different base model / text encoder in Settings, versions with "auto-sync paths" enabled kept showing and using the paths from creation time; reads and enqueued training now follow the global selection.
- **Training task logs showed no step progress (#439)**
  Task logs for Studio-launched training could go a whole epoch without a single step line (output buffering + the progress bar misbehaving outside a terminal); output is now line-by-line in real time.
- **Canceling a task on Windows could leave the training process running (#410)**
  When the process-kill command failed (e.g. access denied), the task showed as canceled while the process kept holding the GPU; termination now falls back to recursively killing the process tree.

## v0.19.0 — 2026-07-14

Retouch & mask brushes with masked loss · zoom and pan everywhere · latent cache in bundles · version-switch consistency fixes · clean Ctrl+C shutdown

### Added

- **Retouch tool: paint over text and watermarks (#393)**
  Preprocessing gains a fifth tool, Retouch: paint over text, watermarks, and clutter with a solid color-picked brush so your LoRA never learns them. Alt-click to sample a color, soft-edged brush, per-image undo/redo (Ctrl+Z); edits stay in memory until you save one image or all at once.
- **Mask brush + masked loss: training skips the regions you mark (#394, #395, #400)**
  The Retouch page gains a Mask mode: brush over regions you don't want trained on (hands prone to artifacts, irrelevant backgrounds), with an eraser and a coverage readout (warns above 50%). Then enable `masked_loss` in the training config's loss group — masked regions are excluded from learning, so generated images fall back to the base model there instead of picking up artifacts from your dataset; grayscale masks give partial weighting. Masks are stored next to each image as `{name}.mask`, follow crop and upscale automatically (restoring the original deletes them), and can optionally be included in bundle exports.

  - `masked_loss` is off by default: the training page points it out when your set has masks but the switch is off, and mask changes automatically invalidate the latent cache. Not yet compatible with NaViT packing (masks are ignored there with a log notice).
- **Bundle export can include the VAE latent cache (#391)**
  When exporting a bundle.zip, you can now include the VAE latent cache (`.npz`) for the training set and regularization set separately; importing on another machine reuses it directly and skips re-encoding (biggest win on machines where encoding is slow). Expect a noticeably larger bundle (about 1 MB per 1024² image, doubled with flip augmentation).
- **Tagging page shows validation set progress (#392)**
  When a version has validation images, the tagging page's right panel gains a "validation set" section: tagging progress and the "to tag this round" estimate are tracked per dataset, and selecting the validation scope no longer shows "—" for the training side.

### Improved

- **Zoom and pan in every single-image view (#396)**
  All single-image views (fullscreen viewer on the Generate page, gallery preview modals across the app, the inline image on the tagging page) now support pointer-centered wheel zoom, drag to pan, and double-click to toggle fit / 100%; the tagging page image is upgraded to full resolution, so zooming in stays sharp.

  - Clicking the image inside a viewer no longer closes it (click and drag-to-pan can't coexist); close with the × button, Esc, or by clicking the edge overlay.
- **Tag autocomplete: suggestions only pop up as you type + global toggle (#401)**
  Clicking into an input to move the cursor no longer pops suggestions over what you're reading — they appear only after the text changes, and clicking the input dismisses an open list. Settings → Tag dictionary gains an "autocomplete while typing" switch to turn it off app-wide.
- **Failed evaluations can be retried from the log entry (#397)**
  When post-training evaluation fails, the evaluation log entry now has a Retry button that re-runs the whole round in one click; previously you had to re-select checkpoints manually. The "Retry" button in the task detail header is renamed "Retrain" for training tasks, making clear it starts training over with the same config rather than re-running evaluation.
- **Readable errors when the T5 tokenizer is missing (#387)**
  When the local T5 tokenizer directory is missing, training downloads it automatically; on flaky networks this used to fail with an inscrutable timeout stack trace. The download is now announced in the log, and failures explain the cause with fix guidance (check your network / download it from Settings / verify the path setting).
- **Curation dataset switch matches the queue page style (#392)**
  The training / validation set switch changes from two tabs to the same single-button toggle as the queue page (labeled with the set you'd switch to), placed at the far right of the header.

### Fixed

- **Stale data after switching versions (#389, #390)**
  In multi-version projects, after switching versions: clicking "Start training" right away could enqueue the previous version, and step pages could keep showing the previous version's data — the curation page in particular kept showing old images while actions applied to the new version. Switching now takes effect immediately and step pages fully reload with the version; switching away from unsaved tag edits asks for confirmation first.
- **Ctrl+C in the terminal couldn't stop the server (#398)**
  With a browser tab open, pressing Ctrl+C used to hang the server at "Waiting for connections to close" forever (a second Ctrl+C didn't help; only killing the process did). One Ctrl+C now exits cleanly within about 3 seconds, without the spurious errors that used to appear during shutdown.
- **Windows training logs no longer show a misleading triton error (#388)**
  With xformers enabled on Windows, logs used to print a harmless `No module named 'triton'` traceback — and when a task failed for an unrelated reason, it could be shown as the failure cause, suggesting you needed to install triton. The probe is now skipped (triton plays no part in the xformers kernels this app uses), keeping logs and failure summaries clean.

## v0.18.0 — 2026-07-09

NaViT packed training · Global WandB presets · Configs persist active fields only · Simplified dedup review · CAME optimizer

### Added

- **NaViT / Patch-n-Pack packed training (off by default) (#371, #372)**
  Training gains a `navit_packing` mode: images of different sizes are packed into a single sequence, with each image attending only to its own content. VRAM utilization is governed by a token budget instead of the "one bucket size per batch" constraint.

  - Optional `navit_native_resolution`: images train at their native size (16px-aligned) instead of being resized / cropped to the bucket grid; images over the token budget are scaled down proportionally by default (or can be made to fail instead).
  - Both are off by default; with them off, training behaves exactly as before.
- **Resolution-aware timestep shift (off by default) (#383)**
  New `timestep_shift_resolution_aware` switch in the training config: when enabled, the timestep shift scales automatically with each image's token count relative to the base resolution (higher resolution → stronger shift), so multi-resolution and NaViT native-resolution runs place every image in an appropriate noise range. Images at the base resolution are unaffected.
- **CAME optimizer (#358)**
  New CAME optimizer option: factorized row / column second moments reduce optimizer-state VRAM, with confidence-guided weighting to suppress the approximation noise the factorization introduces. Six advanced parameters (betas / eps / clip), defaulting to the paper's values.
- **LLM tagging can inject local tagger output (#230)**
  LLM presets gain an "assist tagger" option (off / WD14 / CLTagger): each image is pre-tagged by the local tagger first, and the result replaces the `{{tags}}` placeholder in your prompt as a prior to guide the LLM's caption.

  - Two built-in assist prompt presets ship with `{{tags}}` included (structured caption / single-line natural language); you can also add `{{tags}}` to any preset's prompt yourself. It only takes effect when the prompt contains `{{tags}}`.
- **YAML preview on the training config and presets pages (#366)**
  Both pages can now show the effective config exactly as it will be written to disk and used in training. The presets page's old "TOML preview" was misleading (the fields were never sd-scripts format) and has been replaced by the YAML preview.

### Changed

- **WandB settings moved to global Settings; WandB fields removed from training configs (#367)**
  WandB moves from a per-config override block in the training config to preset-based management in global Settings (Settings → WandB): your API key is no longer written in plain text into config.yaml, task snapshots, exported presets or bundles. Existing global settings migrate automatically; if you ever filled in WandB inside a training config, see the pinned migration post (including the API-key rotation advice).

  - Presets support switching between multiple setups, save-as, and import / export (exports contain the real key — handle with care).
  - The artifact upload settings moved out of the sample-image upload subsection (they were unrelated) and merged into a three-way choice: off / keep latest only / keep all.
  - The `--wandb_*` CLI flags are gone along with the fields; use `WANDB_*` environment variables instead.
- **Training configs persist active fields only (#366, #369)**
  config.yaml, presets and task snapshots no longer include sub-parameters of disabled features or internal defaults — files are much shorter and easier to read. Existing files load unchanged; missing keys fall back to their defaults.

  - This also fixes a real issue: leftover non-default values in hidden fields (e.g. sub-parameters of a previously selected optimizer) could silently affect training. They are now pruned at write time — what you see is what trains.
- **Dedup review simplified to two scan parameters; crops merged into groups (#381)**
  The dedup scan goes from 18 parameters down to two: match scope and sensitivity (loose / standard / strict), with the remaining thresholds fixed as built-in constants. Crop / resize relations are no longer a separate "quality candidates" tab — they join the regular duplicate groups as stricter duplicates, and are only detected under the "duplicates + near-duplicates" scope.
- **Manage tagger models right on the Tagging page (#378, #380)**
  The Tagging page's right panel becomes a "current tagging status" card (tagged count / method / model / trigger word / images this run will process); model download, selection and download-source switching move into each tagger's "advanced parameters" section — no more round-trips to global Settings.

### Improved

- **Sidebar version picker rebuilt as a version row (#384)**
  The sidebar "training version" block becomes a compact version row: switching opens a popover (no longer stretches the sidebar), and hovering reveals create / export / delete. The Overview page's version rail gains the missing delete action, so all four version actions match in both places.
- **Regularization page layout rework (#379)**
  The "Generate" tab is now split into two columns: generation parameters on the left, regrouped into "reg-set settings / image settings", and a new status panel on the right whose "images this run will generate" figure updates live from source / mode / target count, matching the backend's math.
- **Unified actions across preprocessing pages (#381)**
  Tool switching becomes an underline tab row attached to the header, and each page's primary actions move to the top-right of the header. The crop page drops its parameter sidebar to give the workspace more room; "smart clustering" is renamed "auto clustering" and moves into a header popover.
- **Model root migration can merge into existing data (#368)**
  Migrating the model root in Settings no longer refuses when the target already has data: choose "skip existing files" (copies only what's missing — ideal for pointing at a directory shared with other tools) or "overwrite existing files". Copies are atomic per file, so a failure mid-way never corrupts what's already in the target.
- **Queue row actions in their proper place (#370)**
  "Resume training" and the paused-row "resume / cancel" buttons move from the time column into the trailing action column as icons; resume now asks for confirmation, so a stray click can't kick off training.
- **Dataset preview in the prompt picker zooms on click (#375)**
  The dataset image preview at the bottom of the Generate page's "pick prompt from training set" panel now opens full-screen on click, for side-by-side comparison with generated results.

### Fixed

- **Mid-step generation previews no longer show inverted colors (#377)**
  In-progress previews decoded latents with the wrong decoder (Flux instead of the Wan2.1 latent space), producing inverted / garbled colors at a tiny size. They now use the correct projection, with normal colors, filling the result area.
- **Clicking "Generate" while viewing history returns to the live view (#376)**
  Clicking "Generate" while looking at an older image (especially XY grids) used to leave the result area stuck on that old image; it now returns to the live view so you see the new task's progress immediately.
- **HTTPS traffic no longer bypasses the proxy when only one field is set (#374)**
  If either the HTTP or HTTPS proxy field is empty, the other is now used for both (as the settings page always claimed but never implemented): with only an HTTP proxy configured, booru queries and downloads no longer bypass it and time out. With both fields set, each is respected independently.
- **Square images no longer land in an undersized bucket (#313)**
  When several candidate buckets tie on aspect-ratio distance (e.g. multiple 1:1 buckets at base 1536), the bucket closest in area to the base resolution now wins; previously the first generated smaller bucket won (1472×1472 instead of 1536×1536). The frontend bucket preview mirrors the same rule. Affected datasets will bucket slightly differently after upgrading.

### Removed

- **"Blur candidates" removed from dedup review (#381)**
  Blur detection is quality filtering, not deduplication; the tab and its scan logic are gone.

## v0.17.0 — 2026-07-03

Queue page overhaul · Generation task queueing · Scheduled training · Unified VRAM admission · Tagging output format cleanup

### Added

- **Queue page overhaul: sections, all task types, search / filter / pagination (#343, #348, #359, #361, #362, #363)**
  The queue no longer shows training tasks only: training, regularization-set builds, test generation and evaluation sampling now share one queue, split into "Scheduled / Running / Waiting / History" sections, with paginated history.

  - Search by task, config or project name, and filter by type and status; filters are remembered across visits. Defaults to training tasks only — switch to "All" anytime.
  - Task detail pages now adapt to the task type, with a "View result" shortcut (generation tasks jump to their results on the Generate page, regularization tasks to the reg-set page).
  - New "Data jobs" tab: downloads, preprocessing, tagging and evaluation metric jobs are all visible in one place — expand a row for parameters, errors and live logs, cancel it, or jump back to its original page.
  - Tasks and data jobs now share a single ID space; no more two numbering schemes.
- **Generation task queueing: submit back-to-back, unified timeline, full-phase progress (#355, #348)**
  Clicking "Generate" on the test page no longer interrupts a running job: tasks queue up and run in order, and the right panel becomes a unified timeline (queued / running / done) with per-task cancel and a clear-queue button.

  - New batch count next to "Generate": enqueue N tasks at once, with auto-incrementing seeds.
  - The progress bar now covers every phase — model load, text encoding, sampling and VAE decode — instead of sitting at 0% or 100% for long stretches.
  - Generation task logs stream live in the queue detail page, which also links straight back to the resulting images.
- **Scheduled training (#356)**
  When enqueueing a training run you can now pick an exact start time (e.g. 3:00 AM) or a delay in hours; the task waits and joins the queue automatically. The queue page gets a "Scheduled" section with the planned time, a countdown, and "Start now" / cancel actions.
### Changed

- **VRAM scheduling unified into resource-tier admission (#360, #362, #363)**
  Which tasks may use the GPU at the same time is now enforced by the backend in three tiers: exclusive (training / reg AI prior / test generation / evaluation sampling) runs one at a time system-wide; light (tagging / upscaling / evaluation metrics) may run alongside; downloads are unrestricted. This closes three admission gaps, including one where generation could still run during training.

  - **Tagging, upscaling and evaluation metrics now run alongside training by default** (previously deferred). You can turn this off in Settings; the old `allow_gpu_during_train` switch is deprecated and replaced by `light_tasks_during_train`, without migrating the old value.
  - Exclusive tasks run strictly in enqueue order — no more implicit priority; the queue order you see is the execution order.
  - "Generate" is no longer greyed out while training: submissions simply queue up and start once training finishes.
- **Local tagging output format now follows the output, no manual choice (#353)**
  The output-format selector on the Tagging page is gone: local taggers (wd14 / CLTagger) and LLM text mode always write `.txt` (trigger word first); LLM categorized-JSON mode writes `.json`; images that already have `.json` keep getting `.json` updates.

  - `.txt` captions now honor `tag_dropout` (previously JSON-only); the `keep_tokens` prefix stays exempt from shuffle and dropout, matching kohya semantics.
  - Existing flat-JSON datasets are unaffected — the training side keeps reading them indefinitely.

### Fixed

- **Datasets tagged locally with JSON output no longer train on empty captions (#352)**
  Flat JSON written by the local taggers was misdetected by the training side; the parse failure was silently swallowed and those images trained with empty captions (not even the trigger word). Reading is fixed, and a pre-training check now lists any unparsable JSON captions and refuses to start instead of failing silently.
- **`lora_reg_dims` per-layer ranks were silently ignored for `algo=lora` (#350)**
  Since v0.10.0, training with `algo=lora` + `lora_reg_dims` silently ignored the per-layer ranks (the network trained at the global rank with no warning; LoKr was unaffected). After the fix, retraining with the same config actually applies the per-layer ranks.

  - Note: resuming or continuing an old checkpoint of this kind (uniform rank) on the new version fails with a shape mismatch — drop the `lora_reg_dims` setting or retrain. To check whether a run was affected: its `run.log` shows only `[lora_reg_dims] skipped N modules` and no `applied rank overrides`.
- **"Sample prompts" on the training config page accepts newlines again (#364)**
  The multi-prompt rotation field (one prompt per line) swallowed the Enter key, making multi-line input effectively impossible. Fixed; the three sampling prompt boxes on that page also auto-grow with content now.
- **Announcement center no longer jumps back to the first post (#354)**
  Clicking another post right as the announcement center opened could get overridden by the "select first post" default. Fixed.
- **Projects page header stays pinned while scrolling (#347)**
  The header no longer scrolls away with the project list, matching the queue page.

### Removed

- **Queue import / export removed (#363)**
  The "Export / Import" buttons on the queue page and their endpoints are gone. Tasks and data jobs now live in a single ledger; to move between machines, migrate the `studio_data` directory instead (see the data-directory section in Settings).

## v0.16.0 — 2026-06-29

In-app announcement center · app moved back to the root URL · instant-apply settings · faster Generate page · LoRA evaluation (experimental) · several training and UI fixes

### Added

- **In-app announcement center — a bell in the top-right for updates and migration notes (#336, #337, #339).**
  Until now nothing told you what changed in a release or warned you about behavior changes. An announcement now pops up once after each update, and the bell is always there to open.

  - Version list on the left, post body on the right, with full markdown (headings / lists / links / code).
  - The changelog moved from "dig through Settings" into the announcement center.
  - Posts are grouped into changelog / notice / migration; behavior changes that need your attention (like this release's URL move) are pinned separately.
- **LoRA training evaluation (experimental) — automatic quality metrics on checkpoints after training (#138, #319, #322, #323, #324).**
  Landed as the foundation for upcoming evaluation work. The current metrics have limited discriminative power on anime-domain outputs and are for reference only; they are opt-in and not the focus of this release.

  - After training, eval samples are generated and scored with CLIP-T / CLIP-I / DINO-I, plus anime-domain tag recall and character consistency (CCIP), compared against a base-model baseline to isolate the LoRA's net gain.
  - You can hand-pick a validation set per project; eval progress and logs feed the shared task log drawer.
- **Editable project slug on creation, and selected project kept across pages (#333).**
  Project names without Latin characters used to collapse to `project` on disk and got hard to tell apart; picking a project and switching to Generate / Queue also dropped the selection.

  - The new-project dialog adds a "project slug" field that validates live and previews the final on-disk name (leave it blank to derive from the title as before).
  - The selected project stays in the sidebar when you move to global pages like Queue or Generate — no need to reselect from the list.
- **Image counter ("N / M") at the bottom of the large-image viewer (#326).**
  When browsing large images with ←/→ across Download / Preprocess / curation / regularization / training samples / XY grid, the viewer now shows your position in the sequence.

### Changed

- **App moved back to the root URL; the `/studio/` prefix is gone (#334).**
  The address changes from `localhost:8765/studio/` to `localhost:8765/`, which also fixes deployments that reverse-proxy the container port to root (e.g. ModelScope / HuggingFace Spaces) failing to load.

  - Old `/studio/...` links still redirect automatically this release and will be removed in the next one — update your bookmarks.
  - See the pinned "App moved to the root URL" migration post for details.

### Improved

- **Global Settings is now instant-apply; the bottom save bar is gone (#340).**
  Toggles and dropdowns save on change; text and number fields save on blur or Enter. A save indicator sits in the bottom corner — no more "Save" button.

  - Destructive actions (delete a preset, restore dictionary defaults, remove a custom local model) ask for confirmation first.
- **The Generate page opens noticeably faster (#327, #328).**
  Two causes of slow loads with many history images and many projects / versions are fixed.

  - The history rail is now virtualized and reads PNG metadata straight from the text chunk (local test: history scan 15.4s → 0.12s).
  - The LoRA list loads lazily — opening the page no longer fires that batch of project / version requests unless you open the LoRA picker.
  - XY results freeze once generation starts; changing an axis mid-run only affects the next run instead of corrupting results already produced.

### Fixed

- **Fixed fp16 dtype mapping and GradScaler for fp16-only GPUs like the V100 (#335).**
  Corrects the fp16 dtype mapping and GradScaler persistence so cards that only support fp16 (e.g. the V100) train correctly.
- **VAE tiling logs during the cache stage no longer spam or mislead (#332).**
  During latent caching, every image logged a tiling decision (200 images, 200 lines) reading "used > total VRAM" as if memory were exhausted. The tiling itself is correct (it avoids the VRAM paging cliff); this release de-duplicates and demotes those logs.
- **Added a cancel button for AI-prior generation, made the settings drawer dismiss on sidebar click, and stabilized the version panel on load (#329).**

  - The regularization "AI prior" run now has a cancel button (previously only booru scraping did).
  - The settings drawer now dismisses when you click the sidebar, not just the main area.
  - The version "what's new" panel no longer jumps in height while loading or switching versions.

## v0.15.0 — 2026-06-23

Multi-resolution training + CLTagger V2 + custom base models + a movable model root directory + Settings redesign + localized error messages + various self-update / ONNX fixes

### Added

- **Multi-resolution training: mix several base resolutions in one run + configurable bucket aspect ratios + a bucket-distribution preview (#296)**
  Official reference LoRAs often mix several resolutions (e.g. 512/768/1024) to improve high-resolution inference; until now the trainer only supported a single base resolution, and works with extreme aspect ratios were hard-cropped by a fixed 2:1 bucket. This version adds multi-resolution training while keeping the existing aspect-ratio bucketing.

### Fixed

- **Fixed onnxruntime-gpu installing the CUDA 13 build by mistake on Linux, crashing tagging (#311)**
  After installing the ONNX CUDA build, Linux users saw tagging fail with `libcudart.so.13` not found and a misleading "onnxruntime not installed" — the package was actually installed, it just failed to load.

  - Root cause: the default PyPI wheel for newer onnxruntime-gpu (from 1.27 on) switched to CUDA 13, while this project is built end-to-end for CUDA 12 (torch is cu128, the preloaded libraries are all `.so.12`), and mixing them crashes at load time.
  - This version installs the matching onnxruntime-gpu build based on torch's CUDA major version, pinning CUDA 12 to the 1.20–1.26 line; when torch later moves to CUDA 13, it will switch to the corresponding build automatically.
  - The Settings → ONNX Runtime info box adds a line showing torch's current CUDA major version, with a note when there's a mismatch.
  - Users who already have a broken install can run `pip install "onnxruntime-gpu==1.20.1"` and restart to recover immediately; the DirectML / CPU / Windows paths are unaffected.
- **Self-update hardening: npm rewriting the lockfile no longer blocks upgrades + upgrading from old versions no longer re-downloads model data (#308, #310)**
  Two kinds of reliability issues in the WebUI self-update (`git fetch` + `git reset --hard`) are fixed.

  - Newer npm automatically appends metadata like `peer` to `package-lock.json` at startup, making this version-controlled file "dirty" out of nowhere and stalling the "working tree must be clean" pre-update check, so the update button wouldn't respond. As of this version, this kind of automatic rewrite no longer counts as dirty or blocks updates.
  - If the working tree really does have manual changes, a "force overwrite and update" confirmation appears before updating (shared with rollback), so a reset won't silently overwrite your real changes.
  - Early versions had mistakenly committed a few downloaded model data files (tokenizer / config, a dozen-odd MB) to git and later moved them to gitignore; upgrading from a version of that era, `reset --hard` would delete them and force a re-download. This version backs up and restores those files around the upgrade, so old users won't notice (the large weights files were never committed and are unaffected).
- **Fixed grad_accum dropping the last partial group's gradients on small datasets (one fewer step per round) (#305)**
  When a dataset's per-round batch count isn't divisible by the gradient-accumulation step count (`grad_accum`), the gradients of the last under-filled group of batches were discarded and not counted toward training.

  - Extreme case: with 3 images / `grad_accum=4`, an entire round had no update step at all and didn't train.
  - Across multiple rounds, the last group's gradients also leaked into the next round and were normalized incorrectly.
  - As of this version, an under-filled group at the end of each round still steps normally and is normalized by the actual batch count (so the last step's gradient isn't weakened). Configs that already divide evenly, or use `grad_accum=1`, behave the same as before.
- **Fixed a torch.stack crash when training with caching off + batch>1 + non-square images (#299)**
  With latent caching off (`cache_latents=False`) + a batch larger than 1 + a training set whose aspect ratios aren't all the same, training crashed outright with `stack expects each tensor to be equal size`.

  - This path was missing aspect-ratio bucketing, so a batch mixed images of different sizes and crashed at concatenation.
  - The cached path (on by default) already avoided this; this version makes the non-cached path batch by bucket too. Multi-resolution training (new in this version) is especially prone to triggering it with caching off, and it's fixed along with the rest.

## v0.14.0 — 2026-06-19

New SOAP optimizer, LeapAlign self-distillation, and SRA v2 alignment training + Generate page redesign + fix for VAE stalls on high-VRAM cards

### Added

- **New SOAP / Schedule-Free SOAP optimizers for faster convergence on matrix-type adapters (#271)**
  - Two new optimizer types: `soap` (Adam in the Shampoo eigenbasis) usually fits the low-rank matrix factors of LoRA / LoKr faster than AdamW / Prodigy, at the cost of more state VRAM.
  - `soap_sf` layers a Schedule-Free trajectory on top of SOAP — no learning-rate schedule needed, and it eases abrupt style shifts. Like PPSF, it requires the scheduler to be set to none.
- **New LeapAlign two-step leap self-distillation training, with four FlowBP trajectory variants (#277, #278)**
  - Turn it on with `leap_enabled` (under the advanced training options). It builds a two-step leap trajectory on rectified flow so the leap-predicted latent approaches the real latent of the training data — no reward model or full sampling trajectory required, and it fits LoRA fine-tuning.
  - `leap_ratio` controls how much it mixes with standard training; `leap_variant` offers four trajectory-integration methods (following the FlowBP approach): original / sparse / bridge / lagrange, with original as the default to keep behavior unchanged.
  - Mutually exclusive with InfoNoise, loss_weighting, and huber loss (grayed out via the linked front-end controls); these mechanisms are skipped when LeapAlign is on.
- **New SRA v2 self-representation alignment auxiliary loss, aligning intermediate representations to the VAE latent (#279)**
  - Turn it on with `sra_enabled` (off by default, under the advanced training options). It projects the intermediate hidden state of one transformer block back into the VAE latent space and aligns it with the clean latent, acting as an auxiliary regularizer that aids convergence without an extra diffusion forward pass.
  - `sra_weight` (default 0.2) controls the weight and supports none / linear / cosine / jump decay schedules; the projection MLP exists only during training and isn't written into the exported LoRA.
  - `sra_normalize` is on by default: before alignment it standardizes the prediction and target per sample, preventing oversized video-VAE latent scales from throwing the alignment loss off balance.
  - Only attaches to the standard rectified-flow path; not used together with LeapAlign.
- **Project cards can now edit their title and notes, and the action icons appear on hover (#286)**
  - Project cards gain a pencil button for editing the title and notes (notes can be used for search / categorization); the slug and LoRA output name stay fixed, so changing the title doesn't affect any output file name or path.
  - The action icons at the bottom of the card (edit / archive / restore / delete) now fade in on mouse hover or keyboard focus, for a cleaner look the rest of the time.
- **Regularization sets gain a global default set of excluded tags, so you don't re-enter them when switching projects or versions (#285)**
  - Settings → Dataset → Regularization adds a "default excluded tags" field; the regularization set generation page uses it as the initial exclusion seed when that build has no local record yet (common meta tags like watermark / signature / username no longer need to be retyped every time).
  - It's only a seed: you can still add or remove individual tags on the page — it's not a hard filter.

### Changed

- **The Generate page's left-hand config moves to paged tabs, and the prompt picker gains thumbnail previews (#280)**
  - The three blocks on the left — LoRA/XY · Prompt · Config — change from a vertical stack to paged tabs inside one unified card, showing one page at a time, with the current page remembered locally.
  - The prompt picker adds a thumbnail per row and a larger preview at the bottom, making it easier to compare against the generation results on the right.
  - The XY-axis card is tidied up: the axis name gets its own row, the remove button moves to the right end instead of sharing a row with the dropdown, and weights accept a single comma-separated entry (e.g. `0.2, 0.3, 0.4`).

### Fixed

- **Fixed occasional VAE stalls of up to hundreds of seconds during sampling / image generation on high-VRAM cards (#281)**
  - On high-VRAM cards (e.g. 32G), when the working set of a full-image VAE encode/decode approaches about half of VRAM, it triggers system VRAM paging — a single operation degrades from under a second to hundreds of seconds, committed system memory spikes by 20-30G, and it doesn't raise a clean CUDA OOM, so the old "only tile after an error" fallback couldn't catch it.
  - Adds a `vae_tiling` setting (auto / on / off, default auto): it predicts based on live available VRAM and proactively tiles the encode/decode when crossing the cliff, while staying on the fast full-image path with no performance penalty when it doesn't.
- **Fixed the LLM tagger prompt-template input losing focus after a single character (#291)**
  - In the LLM tagger's preset prompt template (the message editor), the input lost focus after every character typed, making continuous typing impossible and forcing repeated clicking. This is now fixed and typing works normally.
  - The same editor is shared between the tagging page and Settings; both are fixed.
- **Fixed the DirectML build of onnxruntime permanently reporting that Studio needs a restart (#292)**
  - Users with onnxruntime-directml (the DirectML backend) installed saw the Settings → ONNX Runtime card persistently showing "restart Studio / the current process is still using the old one," which no number of restarts could clear — even though DirectML was actually working fine.
  - The cause: that package's version number simply differs from its internal onnxruntime core version, and the old logic misjudged a restart was needed based on it. This version judges by the actually loaded execution provider (EP) instead, so it no longer reports falsely.
- **Fixed the pause button only appearing after switching pages once training resumed or started (#287)**
  - After resuming (terminal / paused → resume) or just starting training, the pause button didn't appear on the Monitor / Queue / Overview pages — you had to switch to another page and back for it to refresh.
  - All three pages now listen for events such as the first epoch backup being written to disk and refresh the button state in real time, with no page switch needed.
- **Fixed flash_attn auto-install picking the oldest wheel, leaving newer GPUs without a kernel (#289)**
  - When auto-selecting a wheel, score ties fell back to alphabetical order and preferred the oldest version (e.g. 2.6.3), which has no matching kernel on newer GPUs (e.g. 5090 / Blackwell sm_120) — causing flash_attn to fall back entirely and spam the misleading "only supports Ampere GPUs or newer" message.
  - After the fix, score ties favor the newer version, and both the auto-install and the candidate list put the newest first.

### Improved

- **lycoris LoRA forward defaults to bypass_mode, ~1.8x speedup (#196)**
  Issue #182: at the same model / config (rank=8 / batch=1 / Anima 1024), AnimaLoraStudio's 0.11 it/s was about 1.8x slower than sd-scripts' 0.19 it/s. ### Fixed

- **Several InfoNoise core-algorithm corrections + reg samples excluded by is_reg (#216, #223)**
  An end-to-end mock simulation (96 configs × 4 mmse shapes × 3 grad_accum × 2 baseline × 4 pivot strategies) exposed that the default InfoNoise crammed 99% of the probability mass into the σ_min quartile, so the adaptive sampler never actually took effect. This round fixes 4 algorithm-layer issues + 1 reg-set contamination:

  - **gate pivot `c` default 0.15** (the CIFAR value reported in the paper's §5): the old `above.argmax()`, because the generic 1/σ³ tail saturates `r_norm` to 1.0 at the low-σ end (the warning point in the paper's §B.6), always returned `c ≈ σ_min`, degenerating the gate `σ³/(σ³+c³)` into a near-identity. A new `infonoise_gate_pivot_c` field is an escape hatch: `0` follows the paper-faithful dynamic Eq 87, a positive value overrides explicitly.
  - **`r̂_k = mse / σ²`** (the paper's Appendix B.2 Eq 61, the log-σ entropy rate): the old `mse / σ³` came from the VE channel (Eq 59), inconsistent with summing over `Δlog σ`; the missing Jacobian is exactly what let the generic tail dominate normalization.
  - **`maybe_refresh` gated by `global_step`** (the optimizer step), no longer by `_internal_step` (the micro-batch count): `N_warm` and the default `total_steps × 20%` both assume optimizer steps, so `grad_accum=4` made warmup exit 4x early, going adaptive before the EMA had converged.
  - **`state_dict __version__ = 2`**: σ³ → σ² is a semantic break; resuming a v1 ckpt cold-starts and re-accumulates the EMA with a warning rather than raising, making long-run upgrades safe.
  - **Reg samples hard-excluded from InfoNoise records by the `is_reg` flag** (#223): previously a `loss_weight >= 0.99` threshold skipped reg samples, but the `reg_weight=1.0` boundary let reg still enter the records and contaminate the schedule. This now passes an `is_reg` flag through the dataset layer into the batch, and the loop masks with `~batch["is_reg"]`, decoupled from `loss_weight`. Reg samples still enter the gradient weighted by `reg_weight` as usual — they just don't enter InfoNoise schedule learning.
- **InfoNoise's 4 mutually exclusive field pairs get real-time front-end locking + tolerant disabling for old configs + a top banner (#221, #226)**
  InfoNoise's 4 schema mutual exclusions with `noise_enhancement_type` / `loss_weighting` / `loss_type=huber` / `timestep_schedule_shift` previously had only a backend validator, with no front-end disable_when. You weren't stopped while editing — you had to wait for the 600ms debounced auto-save to pop a `train.saveFailed` toast, with the form still dirty.

  - **Symmetric lock, non-default wins**: the 4 controlled fields get `disable_when=infonoise_enabled==true`; `infonoise_enabled` gets a reverse compound-OR `disable_when`, so when any conflicting field is non-default its checkbox grays out and locks. On a live switch, the other side resets to default automatically.
  - **Tolerant for old configs**: an old yaml with `infonoise=on` plus any conflicting field non-default, when entering the Train page, has the backend `_tolerant_validate` turn InfoNoise off automatically while keeping your original values, so you don't end up with all 4 fields grayed out and locked uneditable.
  - **Top banner**: a "Reset: infonoise_enabled" banner now also lights up on the initial config load (not only the fork-preset / save-as-preset paths), so you can immediately see which field was changed for you.
  - The "strict save" path (front end bypassing disable_when to PUT directly) still errors out, guarding against a silent value change.
- **VAE full-image decode OOM auto-falls back to tiled decode (#207)**
  When generating 1024×1024 reg images on 8GB VRAM, the VAE decode working peak can fill the remaining VRAM and OOM on the very first image. This version adds a try-full + `torch.cuda.OutOfMemoryError` fallback to `_tiled_decode` at the `VAEWrapper.decode` entry (tile=64 latent / 512 px, stride=48, cosine blend mask, fp32 accumulator to prevent bf16 precision loss).

  - **Zero cost on large VRAM**: it passes on the first try and never enters the tile fallback.
  - **Fallback on small VRAM**: a single tile's working peak is ~75 MB, each image is ~30% slower, but it completes.
  - **All 6 call sites benefit automatically**: reg_ai / generate CLI / generate XY / daemon generate / daemon XY / training sample preview share `sample_image` through the same entry.
- **cache_latents deduplicated by npz to avoid re-encoding the VAE for repeat folders (#199)**
  Kohya-style per-folder repeats (a `5_concept` prefix) expand the same image N-fold into `samples`; the old `_build_cache` walked `samples` directly to collect `to_encode`, so the same image was VAE-encoded N times, repeatedly overwriting the same npz — and `flip_augment` mode doubled that again. It now deduplicates by `npz_path`, so first-time cache build time scales with the unique image count; a second run (cache hit) behaves the same.
- **Reg AI priors support JSON captions + tags keep spaces instead of converting to underscores (#185)**
  AI-prior generation previously only read `.txt` captions and auto-converted spaces to underscores, so JSON-caption training sets couldn't be read for AI priors, and prompts became `brown_hair` rather than the space-separated tag format Anima recommends. This version:
  - reads all three caption formats — `.json / .txt / .caption` — keeping the space-separated tag form in the prompt;

### Changed

- **`noise_offset` and pyramid noise change from both-on to a mutually exclusive single choice, aligning with kohya upstream (#175)**
  kohya-ss/sd-scripts PR #477 (2023-05) forbids `noise_offset` and `multires_noise_iterations` from being on together across all models (SD1 / SDXL / SD3 / Flux) — both inject low-frequency content into the noise, and pyramid's lowest-resolution layer ≈ a noise_offset equivalent, so stacking them double-injects low frequencies. Anima's old implementation didn't forbid it, and the normalization at the end of `make_noise` would dilute the constant noise_offset bias added earlier — you'd think both were in effect, when it was effectively "only pyramid running, the offset eaten," which is more insidious than kohya's hard error.

  Adds a `noise_enhancement_type: "none" | "offset" | "pyramid"` field (a frontend dropdown); the mutually exclusive opposing fields auto-hide and are forced to zero. Old yaml migrates automatically: when both are > 0, pyramid takes priority (pyramid was the one actually in effect in the old implementation), and the offset field is zeroed.

### Fixed

- **Generate-page inference aligned with ComfyUI output + LoRA DoRA / rs_lora no longer silently fails (#169)**
  Users reported two separate symptoms: on the Generate page "the LoRA had no effect at all," and the same config produced clearly different output in Studio vs. ComfyUI. Going through the native ComfyUI Anima implementation item by item confirmed 4 alignment bugs at different levels.

  - **LoRA DoRA / rs_lora pass-through**: `read_lora_meta` missed reading the `weight_decompose` (DoRA) and `rs_lora` fields from `ss_network_args`, so `apply_loras` built a network structure inconsistent with training — all 280 of DoRA's `dora_scale` tensors were skipped as unexpected, and rs_lora's α scaling was cut to 1/8 of what training used. The two together are what you perceive as "the LoRA had no effect at all."
  - **T5 token weights take effect**: T5 token weight syntax like `(tag:1.3)` was computed but then discarded by `preprocess_text_embeds`, so the weights had no effect; now, following ComfyUI, the t5xxl_weights are multiplied in after the LLMAdapter output.
  - **Initial noise reproducible across hardware**: `torch.randn(device='cuda')` goes through cuRAND (inconsistent across hardware); switched to a CPU generator + `.to(device)`, so the same seed is reproducible across platforms.
  - **Default negative prompt**: when you leave it blank, it no longer sneaks in a long `"worst quality, low quality, score_1, ..."` string, so the CFG anchor matches ComfyUI.

  After comparing the native ComfyUI Anima implementation file by file in parallel with several agents (VAE / DiT 685 keys / RoPE 3D / Sampler / Scheduler / CFG) and confirming the rest of the path is fully equivalent, this release changes only these 4 spots.
- **cache_latents and flip_augment on together permanently mirror-pollutes 50% of the data (#176)**
  During its cache stage, `CachedLatentDataset` calls `ImageDataset.__getitem__` to get pixels, but the base dataset's `if flip_augment and random.random() > 0.5: img.transpose(...)` rolls the dice during the cache stage — every image is permanently encoded as either flipped or not, and training afterward only reads the npz and never invokes the base flip. The consequence: flip_augment silently does nothing (you think you have data augmentation, but you don't), and 50% of the data is permanently mirror-polluted (a random half of the images get mirrored at each training launch).

  Fixed following kohya-ss/sd-scripts' `ImageInfo.latents / latents_flipped` dual-latent approach: the cache stage encodes single / double copies depending on `flip_augment` (the double stores both `latent` + `latent_flipped` keys in the npz), and at training time `__getitem__` picks which key by `random.random() > 0.5`. The cost: with `flip_augment=True`, both the encode time and cache size are ×2, but flip really takes effect in training.

  Old caches self-heal: `_is_cache_valid` invalidates and re-encodes when `flip_augment=True` but the npz is missing the `latent_flipped` key; conversely, with `flip_augment=False` the double copy is still valid (a superset), so toggling the switch doesn't re-encode back and forth.
- **Generate-page XY grid mixed in LoRAs that were never selected (orphan anchor buildup, since v0.8.0) (#167)**
  In XY mode users kept seeing "LoRAs they never selected" mixed in: the XY axis had chenbin V3.4 selected, yet every cell got pinned with an unselected chen-bin v3.2 or a cross-mode hoshi. It reproduced even after clearing localStorage / switching to an anonymous browser, unrelated to the frontend cache.

  Root cause (present since the v0.8.0 XY feature): the only entry point that adds an anchor to the LoRA bucket in XY mode is the `lora_ckpt` axis picker, but it "only pushes, never prunes" — switching project / switching axis type / deleting the Y axis only clears the axis binding, leaving the bucket's anchors untouched. The XY sidebar has no base-LoRA list UI, so you can't see or delete them. At submit, the old logic sent the whole bucket as base LoRAs, and the backend stacked them onto every cell, so the orphan LoRAs appeared constantly in every image. Past fixes (including the recent dual-bucket split) only addressed cross-mode bleed and never touched the in-bucket orphan buildup + sending the whole bucket as base.

  Fix: extracted a pure function `buildXYMatrix` that, at submit, keeps only the anchors referenced by the X / Y axis `loraIndex`, remaps the indices in order of appearance, and discards orphans; `lora_configs` is empty for non-lora_ckpt axes.
- **Generate-page enqueue race (`config not found`) + LoRA bleed across single / xy modes (#159)**
  - **Enqueue race**: `enqueue_generate` first writes the task as `pending+generate` (which makes it dispatchable), then builds the config (including the time-consuming `detect_attention_backend`) and writes `config_path`. The supervisor ticks every 1s; if it dispatches in the window where "`task_type` is already generate but `config_path` is still NULL," the daemon reads an empty path and goes straight to failed. Changed so `_dispatch_generate` skips tasks whose `config_path` isn't in the db yet (dispatched on the next tick), and marks a task failed when config build fails to avoid it staying pending forever.
  - **LoRA bleed across single / xy modes**: `loras` was persisted as a single shared array, so adding A in single, switching to xy and adding B, made xy generate with A+B, and switching back to single showed A+B too. Split into `singleLoras` / `xyLoras` dual buckets routed by mode (compare shares the xy bucket), with old config auto-migrated into one copy in each bucket so selections aren't lost.
- **XY lora_ckpt axis ordered by the ckpt display order, no longer jumping around by click order (#164)**
  On the Generate page's XY grid, the `lora_ckpt` axis (sweeping the same LoRA's different epoch / step checkpoints to find the overfitting inflection point), when multiple ckpts are selected, ordered the axis values by the order you clicked the chips, not by epoch / step. The consequence: picking ep80 / ep60 / ep40 in a jumbled click order (80 → 40 → 60) laid out the grid columns as `[80, 40, 60]`, dropping ep60 at the end so the eye couldn't follow the "more overfitting the later you train" trend and the inflection point couldn't be read.

  Root cause: `InlineLoraPicker` stores the multi-select in a `Set<string>`, and at commit `Array.from(set)` takes the Set insertion order = click order. Changed to the canonical sort already computed by the backend's `list_lora_ckpts` (`final → step↓ → epoch↓ → other natural order`, which the picker already renders the chips in).
- **`sample_seed=0` resolved at training start, same prompt and noise across epochs (#193)**
  The semantics of `sample_seed=0` is "random seed" (stated in the schema description), but the old implementation's `if s_seed:` skipped the set-seed entirely and relied on the global torch RNG throughout. The global RNG is consumed by dropout / timestep / noise / dataloader at every training step, so its state is completely different by the time each epoch reaches the sampling point — the same prompt produces a different image at different epochs. Sample images across epochs are meant to show "the convergence process / overfitting trend," which assumes the noise is fixed so only the model changes; the old behavior changed the noise too, ruining the comparison.

  Following kohya-ss/sd-scripts' standard approach: during the training bootstrap, if `sample_seed` is 0 / unset, draw a random seed once, write it back to `args.sample_seed`, and log it, so the whole run uses the same prompt and same seed. pause / resume freezes through the snapshot, so it uses the same seed across pauses; if you restart a task while the yaml is still 0, it draws a new random one.
- **Windows launch reports npm WinError 193 (npm resolution prefers `.cmd`) (#140)**
  Launching `python -m studio` on Windows reported `OSError: [WinError 193] %1 is not a valid Win32 application`, with the stack hitting `subprocess.Popen([npm, ...])`. Root cause: `find_npm`'s candidate order let `shutil.which("npm")` match `C:\Program Files\nodejs\npm` first — that's the bash script (no extension) the official Node.js installer ships for Git Bash / MSYS, which `CreateProcess` can't launch directly.

  Fix: the Windows candidates are reordered to prefer `.cmd` → `.ps1` → bare name as fallback; on a `.ps1` hit it auto-wraps with `powershell.exe -NoProfile -ExecutionPolicy Bypass -File`. Linux / Mac are narrowed to `("npm",)` by `os.name`, so their behavior is completely unchanged.
- **`studio.sh` now pauses on a launch error instead of flashing closed (so double-click users can see the error) (#174)**
  When Node.js isn't installed, `studio.sh` only printed a single `Exit code 2` line and exited, so users launching from the file manager or a non-persistent terminal saw the error flash by and disappear. `studio.bat` has long had a `pause >nul` backstop; this release gives `studio.sh` the matching handling — a nonzero rc + a TTY prompts to press Enter before exiting; a normal exit / Ctrl+C / non-TTY (CI / pipe) is skipped to avoid a false hang.
- **Missing SOCKS5 proxy dependency caused base-model download to report `socksio not installed` (#190)**
  After configuring a `socks5://...` proxy, downloading the base model reported `Using SOCKS proxy, but the 'socksio' package is not installed`. Root cause: `requirements.txt` didn't declare the extras SOCKS5 needs. The two download paths use different HTTP clients, each needing a different SOCKS backend — HuggingFace (httpx) needs `socksio`, booru / ModelScope (requests) needs `PySocks`. `requirements.txt` is changed to `requests[socks]>=2.31.0` + an explicit `httpx[socks]>=0.27`, with each extra serving its own path, and no C extensions so it's cross-platform fine.

## v0.8.3 — 2026-05-19

Hotfix: ARB bucketing no longer drops images from small buckets + the per-epoch step count is computed per bucket

### Fixed

- **Fixed a bug where an ARB bucket's tail was dropped whenever it held fewer than batch_size images (short batches are now kept, matching kohya / ai-toolkit)**
  `BucketBatchSampler` defaulted to `drop_last=True`, so `len(bucket) % batch_size` images were dropped from every ARB bucket. Worst of all, **a bucket smaller than batch_size was dropped entirely** — at batch_size=2, for example, every bucket holding a single odd-aspect-ratio image would never be trained on.

  Tracing the git history: `drop_last=True` was written into the very first ARB version (commit `6774079`, "feat: add arb", 2026-02-08) with no commit message or ADR explaining the intent — it was likely carried over from PyTorch `DataLoader`'s sanitary default. But in the ARB case the trade-off has flipped: a plain DataLoader drops one remainder per epoch, whereas ARB drops one remainder per bucket, so the loss scales linearly with the number of buckets.

  - `phases/dataset.py`: `drop_last=False`, matching the "keep short batches" semantics of kohya `sd-scripts` (`math.ceil(len/bs)`) and ostris `ai-toolkit` (`min(end_idx, len(bucket))`)
  - Diffusion DiTs use LayerNorm/GroupNorm and are insensitive to dynamic batch sizes; `loop.py` already reads the batch size dynamically from `latents.shape[0]`, so a short batch introduces no numerical issues
- **The per-epoch step count is now computed exactly per ARB bucket (it was previously too low, leaving the LR scheduler misaligned near the end)**
  `__len__` previously used the global `n // batch_size` (or `ceil(n/bs)`), but the actual ARB batch count is `Σ_b f(n_b, bs)`, since each bucket has its own remainder. The global formula underestimated the batch count → `steps_per_epoch` was off → the scheduler's `total_steps` was off → the learning rate was misaligned over the final few steps.

  For example: a dataset of 129 images with batch_size=2 logged "steps per epoch: 64" (= 129 // 2), but the actual per-bucket floor sum comes out smaller (each bucket loses one remainder). The fix iterates over `bucket_for_index` and sums the per-bucket floor/ceil counts.

  Added `tests/test_bucket_batch_sampler.py` covering: small buckets aren't dropped, the historical drop_last=True behavior, `__len__` computed per bucket, `__len__` equaling the number of batches actually yielded, and falling back to the global formula when no bucket info is available.

  - A fullscreen preview replaces the popup preview
  - Keyboard accept / remove shortcuts make working through images one at a time faster

### Fixed

- **onnxruntime-gpu silently downgraded to CPU on Windows / Linux (#29, #30)**
  Root cause: when the CUDA EP fails to dlopen, onnxruntime doesn't raise — it silently falls back to CPU internally; `ort.get_available_providers()` still reports CUDA as available, the UI looks fine, and all you see is CPU usage spiking.

  - Added monitoring: `_create_session` compares against the actual `session.get_providers()`, and if CUDA was requested but isn't actually active it reports `cuda_load_error` so the UI can surface it
  - Windows: Python 3.8+ dropped automatic DLL loading from PATH, so we added `os.add_dll_directory(torch/lib)` to let onnxruntime find torch's bundled `cublasLt64_12.dll` / `cudnn_*.dll`
  - Linux: the worker subprocess now explicitly does `import onnxruntime_setup` at the top to trigger preloading; fixed a misjudgment in `_has_system_cuda_libs()` (cloud images with the CUDA Toolkit but no cuDNN used to be mistaken for a complete system CUDA install, which skipped preloading)
  - Added a `tools/diagnose_onnx_gpu.py` diagnostic script
